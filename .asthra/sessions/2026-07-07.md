
## Task 15 — Permission Schema System [COMPLETED]

**Goal**: Declarative permission schema for all settings pages. A `GodModeSchemaPanel` that shows ALL schema-defined elements (including hidden ones never rendered), complementing the auto-overlay which only shows elements actually can()-checked.

**Files created**:
- `frontend/src/lib/permission-schema.ts` — `PageSchema`, `PageSchemaElement` types + `PAGE_SCHEMAS` (9 pages) + `findSchemaForRoute(pathname)`
- `frontend/src/hooks/use-page-permissions.ts` — `usePagePermissions()` hook. Returns `{ schema, visible }`. In God Mode edit mode: proactively registers ALL schema permissions via `useGodModeTracker.getState().registerPermissionCheck`.
- `frontend/src/components/platform/schema-gate.tsx` — `SchemaGate({ elementKey })` — looks up permission from schema, behaves like `PermissionGate` in edit mode (+/- overlay).
- `frontend/src/components/platform/god-mode-schema-panel.tsx` — `GodModeSchemaPanel`. Fixed `right-4 top-16` panel. Shows all schema elements with type icons, Eye/EyeOff visibility indicators, +/- buttons for permissioned elements. Calls `usePagePermissions()` internally.

**Files modified**:
- `frontend/src/layouts/asthra-shell.tsx` — imports and mounts `<GodModeSchemaPanel />` alongside `<GodModeAutoOverlay />`
- `frontend/src/app/settings/organizations/[id]/page.tsx` — replaced `PermissionGate` with `SchemaGate` for all 5 OrgTabs + 2 save buttons; added `usePagePermissions()` call; removed `PermissionGate` import
- `frontend/src/app/settings/members/page.tsx` — added `usePagePermissions()` call
- `frontend/src/app/settings/organizations/page.tsx` — added `usePagePermissions()` call

**TypeScript**: `npx tsc --noEmit` — passed (exit code 0)

**Build**: `npm run build` — running (background, tsc clean)

**Key design decisions**:
1. `SchemaGate` replaces `PermissionGate` in migrated pages — permission code lives in schema, not in page JSX
2. Schema panel is globally mounted → works for all 9 schema pages even unmigrated ones
3. Per-page `usePagePermissions()` calls are additive (idempotent) — self-documentation only
4. `PAGE_SCHEMAS` covers all 9 settings pages ahead of migration to give full panel coverage immediately

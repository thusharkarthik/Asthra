# 2026-07-13

## Organization Archive / Restore Visibility Stabilization

Fixed organization lifecycle visibility on `/settings/organizations/:id`.

Root cause:

- The runtime Archive/Restore block was wrapped in `SchemaGate elementKey="danger_zone"`.
- `danger_zone` mapped to `settings.organization.delete`, so users with correct `settings.organization.archive` or `settings.organization.restore` permissions could still lose the action.
- The route used platform context organization lists as the organization state source; inactive organizations can be absent from those lists, which made restore state unreliable after refresh.

Changes:

- Organization settings route now fetches `GET /organizations/{id}` for canonical route state.
- Organization page access allows explicit view/manage/edit/archive/restore route-scoped permissions.
- Archive/Restore actions are gated directly by `settings.organization.archive` / `settings.organization.restore`.
- Removed the delete-based `danger_zone` schema wrapper from the runtime lifecycle action.
- Archive/restore mutation updates organization detail cache and invalidates organization list/detail, platform context, context version, and scoped permission queries.
- Updated RBAC certification report, bug memory, and architecture decisions.

Validation:

- `npm run build` in the repository still fails on pre-existing `.next` EACCES ownership artifacts.
- `npm run build` passed from a clean `/tmp/asthra-frontend-verify` copy with repo `node_modules` symlinked.

## Organization Settings Optional 404 Handling

Fixed the application error that appeared after organization Archive/Restore.

Root cause:

- Archive/Restore itself succeeded through `PATCH /organizations/{id}`.
- The page then refetched `GET /organizations/{id}/settings`.
- The active Core backend does not implement that settings endpoint, so it returned 404.
- The page treated that optional settings query as a normal failure path, causing the app error until refresh.

Changes:

- `settingsApi.getOrganizationSettings()` now catches 404 and returns safe default organization settings.
- Archive/Restore invalidation no longer forces `["org-settings", orgId]` to refetch.
- Canonical org lifecycle state remains sourced from `GET /organizations/{id}` and org list/platform context refreshes.
- Updated bug memory and RBAC certification report.

- `./node_modules/.bin/tsc --noEmit` passed from a clean `/tmp/asthra-frontend-tsc` copy with repo `node_modules` symlinked.

## AsthraShell Skipped-Onboarding Update Loop

Fixed the React maximum update depth error that appeared after organization Archive/Restore.

Root cause:

- Archive/Restore invalidates platform context and refetches organization data.
- `AsthraShell` had an effect that called `setSkippedOnboardingUserId(null)` whenever `organizations.length > 0`.
- The setter ran even when skipped onboarding state was already `null`, so post-action context refreshes could repeatedly re-enter the setter path.

Changes:

- The shell now clears skipped onboarding only when `skippedOnboardingUserId` is non-null.
- The clear is scoped to the current user id when available.
- The effect dependency list now includes `skippedOnboardingUserId` and `currentUser?.id`.

## PlatformContext Stable Workspace Sync Key

Fixed the remaining workspace-store maximum update depth loop after organization Archive/Restore.

Root cause:

- The workspace store setter had been hardened, but `PlatformContextProvider` still ran the sync effect whenever the full `contextQuery.data` object identity changed.
- Archive/restore invalidates platform context, and refetches can return a new object identity even when workspace-scope data is effectively unchanged.
- That allowed repeated calls into `setPlatformContext` during post-action refetches.

Changes:

- Added a stable workspace sync key based only on current org/workspace/project ids and organization/workspace/project id/parent/lifecycle snapshots.
- Split workspace-store sync and auth-user sync into separate effects.
- Workspace-store sync no longer depends on permissions, navigation, modules, feature flags, AI/config/search metadata, or query object identity.
- Auth user state still syncs from a separate user key.

## PlatformContext Workspace Store Sync Loop

Fixed the second React maximum update depth error after organization Archive/Restore.

Root cause:

- Archive/Restore invalidates platform context and refetches organization/scope data.
- `PlatformContextProvider` syncs unified context into `workspace-store` through `setPlatformContext`.
- The store accepted current org/workspace/project ids even when those ids were not present in the incoming arrays, which can happen around inactive organization filtering.
- The equality guard compared only ids, so lifecycle-relevant state and invalid selected ids could keep the context/store sync path unstable.

Changes:

- `setPlatformContext` now validates current organization/workspace/project ids against incoming arrays before selecting them.
- Equivalent platform context syncs are skipped when selected ids and entity id/version/active snapshots are unchanged.
- Real lifecycle/entity changes still update the store.

## PlatformContext Workspace Sync Replay Guard

Tightened the remaining PlatformContext -> workspace-store sync path after Archive/Restore.

Root cause:

- The previous stable sync key still included volatile `updated_at` fields.
- `PlatformContextProvider` did not keep a last-synced-key ref, so equivalent context refetches with new object identities could still call `setPlatformContext`.
- `workspace-store` also treated timestamp-only changes as workspace state changes.

Changes:

- Workspace sync keys now include only stable scope data: current org/workspace/project ids, organization id + active state, workspace id + organization id, and project id + workspace id.
- Added a provider ref guard so the same workspace sync key is not applied twice for the same access token.
- Updated workspace-store no-op comparison to use sorted stable snapshots and ignore timestamp-only changes.

Validation:

- Safe frontend type validation passed from a clean `/tmp/asthra-frontend-tsc` copy with repo `node_modules` symlinked.

## Task 4 — Settings Authority Context + Conditional Home Page

**Branch**: `fix/settings-members-authority-scope`

### What changed

**`frontend/src/app/settings/layout.tsx`** (updated):
- Added `SettingsAuthorityValue` type and `SettingsAuthorityContext` (exported).
- Added `useSettingsAuthority()` convenience hook (exported).
- Changed org/workspace authority detection from `.some()` to `.find()` to capture `scope_id` for the context value.
- Every `return <>{children}</>` branch now wraps children in `<SettingsAuthorityContext.Provider value={...}>` with the resolved `authorityLevel`, `orgId`, and `workspaceId`.
  - Superuser → `{ authorityLevel: "superuser", orgId: null, workspaceId: null }`
  - Platform admin/owner → `{ authorityLevel: "platform", orgId: null, workspaceId: null }`
  - Org admin/owner → `{ authorityLevel: "org", orgId: assignment.scope_id, workspaceId: null }`
  - Workspace admin/manager → `{ authorityLevel: "workspace", orgId: null, workspaceId: assignment.scope_id }`
  - Personal routes (member) → `{ authorityLevel: "member", orgId: null, workspaceId: null }`
- Default context value is `{ authorityLevel: null, ... }` — treated as "show everything" for backward compatibility.

**`frontend/src/app/settings/page.tsx`** (updated):
- Imports `useSettingsAuthority` from layout and `SettingsLayout`/`SettingsSectionHeader` from settings-components.
- If `authorityLevel === "member"`: renders 4 personal cards (Profile, Preferences, Notifications, Account) inside a `SettingsLayout`.
- All other authority levels (and the `null` default): renders `<SettingsHomeView />` unchanged.

- `null` default for `authorityLevel` in the context ensures pages rendered without the layout (i.e., in unit tests) still show the admin view — no test changes needed.

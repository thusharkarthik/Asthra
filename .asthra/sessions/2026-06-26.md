## Fix 2 — Member List Cache Invalidation (Frontend)

### What changed

**`frontend/src/components/settings/settings-admin-views.tsx`**:
- Added `["settings", "members"]` and `["settings", "global-member-role-assignments"]` to `invalidateSettingsAndContext()`.

**`frontend/src/hooks/use-settings-mutations.ts`**:
- Added the same two invalidation keys to `useInviteMemberMutation.onSuccess` and `useAssignRoleMutation.onSuccess`.

### Root cause
`invalidateSettingsAndContext` invalidated `queryKeys.members.all` = `["members"]`. TanStack Query prefix-matches this — it matched `["members", "list", ...]` (global directory) but NOT `["settings", "members", orgId, wsId]` (scoped member list) because that key lives in the `"settings"` namespace.

## Role Assignment Unification — user_roles → role_assignments dual-write

**Branch**: `fix/settings-members-authority-scope`

### Goal
Decommission user_roles as the primary write path. Make role_assignments the authoritative store for scoped role data. Add `platform_member` as a default invite role. Fix invite modal with dynamic scope dropdowns.

### Backend files changed

**`services/core-service/app/schemas/role.py`**:
- Added `scope_type: str = "platform"` and `scope_id: int | None = None` to `UserRoleCreate`.
- Backward-compatible defaults — all existing callers that don't supply scope get platform/None.

**`services/core-service/app/services/role_service.py`**:
- Added `from datetime import datetime, timezone` import.
- Added `platform_member` to `ASTHRA_ROLE_TEMPLATES` (scope: platform, permissions: settings.profile.view, settings.notifications.view, settings.preferences.view). Positioned after `platform_support`, before `organization_owner`.
- Rewrote `assign_user_role()`:
  - Uses caller-supplied `scope_type` and `scope_id` instead of hardcoded `"platform"`/`None`.
  - Primary duplicate check now on `role_assignments` at the specific scope (not user_roles globally).
  - Dual-writes: still writes to `user_roles` for backward compat (skips if entry already present); also writes to `role_assignments` with full scope info (creates or reactivates).
  - Calls `ContextVersionService.bump_access(scope_type, scope_id)` with the actual scope.

**`services/core-service/app/services/access_control_service.py`**:
- `_resolve_roles()`: added `and role.scope == "platform"` guard when iterating `UserRole` rows.
- Non-platform roles in `user_roles` are no longer treated as platform-scope. Their correct scoped entry comes from `role_assignments`.

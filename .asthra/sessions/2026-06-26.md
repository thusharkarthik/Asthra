## QA Bug Fixes — Role Assignment Unification Follow-up

**Branch**: `fix/role-assignment-unification`

### Bug 1 — Settings don't unlock without page refresh after role assigned

**Root cause**: Role-assignment mutations invalidated member list queries but NOT the authority queries used by `settings/layout.tsx` (`["members-page", "platform-permissions"]`, `["members-page", "my-role-assignments", userId]`, `["settings", "roles"]`). These have `staleTime: 60_000` and never re-ran after role changes.

**Files changed**:
- `frontend/src/hooks/use-settings-mutations.ts` — added `["members-page"]` and `["settings", "roles"]` to `useInviteMemberMutation.onSuccess` and `useAssignRoleMutation.onSuccess`
- `frontend/src/components/settings/settings-admin-views.tsx` — added `["members-page"]` and `["settings", "roles"]` to `invalidateSettingsAndContext()`, `MembersView.roleMutation.onSuccess`, `MemberDetailView.assignRoleMutation.onSuccess`, and `MemberDetailView.removeRoleMutation.onSuccess`

### Bug 2 — Invite button hidden when no orgs exist

**Root cause**: Button wrapped in `!isGlobalDirectory || organizations.length ? ... : undefined`. When global directory AND zero orgs, both are false, button disappears.

**Fix**: Removed the ternary wrapper. `PermissionAction` already gates on `settings.member.invite`. Updated info card text to clarify platform-scoped roles can be invited without an org.

### Bug 3 — Platform Member invite shows wrong scope error

**Root cause**: `submitInvite` required non-null `effectiveOrgId` for all roles. For platform-scoped roles in global directory, `scopeOrganizationId = null`, triggering "Unable to determine organization scope." Scope display also showed "No scope" message.

**Fix**:
- Changed org guard to only fire when `needsOrg` (non-platform scope roles)
- Platform invites pass `organization_id: null` to API (mutationFn accepts `number | null`, casts to `any` for API call)
- Scope display for platform roles: "Platform scope (no additional scope required)"

### Bug 4 — Non-platform roles not appearing in Current Roles after assignment

**Root cause**: "Current Roles" card read from `userRolesQuery` (`user_roles` table). But `assignRoleMutation` calls `createRoleAssignment` → `POST /role-assignments` which writes only to `role_assignments`. The two tables diverged.

**Fix**:
- "Current Roles" now reads from `activeAssignments` = `roleAssignmentsQuery.data.filter(a => a.status === "active")`
- `memberRoleIds` and `availableRoles` derived from `activeAssignments`
- `removeRoleMutation` now calls `deleteRoleAssignment(assignment.id)` instead of `removeUserRole(role_id)`
- Remove button passes `assignment.id` (from `RoleAssignmentRecord`), not `role_id`
- Scope column now shows `scopeLabelForAssignment(assignment, organizations, workspaces)` — org/workspace name if available
- Assigned date uses `assignment.assigned_at` (from `role_assignments`) instead of `assignment.created_at`

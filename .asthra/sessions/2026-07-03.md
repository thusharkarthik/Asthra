## Task: Hard Reset Shows Onboarding Gate Instead of /login (BUG-043)

### Goal

Fix the bug where an expired/invalid token causes the app to show the onboarding gate instead of redirecting to `/login`. Root cause: stale `isAuthenticated=true` in localStorage bypasses the auth redirect effect; when platform context returns 401, `contextIsError=true` + `organizations=[]` makes `needsOnboarding=true`.

### Files Changed

- `frontend/src/layouts/asthra-shell.tsx` — 4 targeted changes:
  1. Added `isError: contextIsError, error: contextError` to `usePlatformContext()` destructure
  2. Added `!contextIsError` to `needsOnboarding` condition
  3. Added `useEffect` to call `logout()` when context returns 401 (clears all stores + redirects)
  4. Added synchronous `return null` guard (between context-loading gate and onboarding gate) to prevent rendering while redirect fires

### Guard Order After Fix

`public path` → `hydration/auth` → `context loading (initial)` → `401 null guard` → `onboarding gate`

### Edge Cases Verified (by design analysis)

1. No token (cleared localStorage): `isAuthenticated=false` → existing guard catches it ✓
2. Expired token → 401: new `contextIsError` effect + null guard catches it ✓
3. Valid new user, no org: `contextIsError=false`, `needsOnboarding=true` → onboarding gate ✓
4. Valid existing user: `contextIsError=false`, `organizations.length>0` → normal shell ✓
5. Public path: `isPublicPath=true` → effect skipped, guard skipped ✓

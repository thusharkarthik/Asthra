## Core Invitations Manual QA Bug Fix

- Fixed follow-up browser QA defects from the Core Invitations certification pass.
- Confirmed the persisted-success / UI Internal Server Error root cause from Core logs: `InvitationRepository.add_memberships()` inserted a duplicate `role_assignments` tuple and hit the database unique constraint when a stale/inactive same user/role/scope assignment already existed.
- Invitation membership assignment now reactivates stale same-scope role assignments instead of inserting duplicates, and invite create refreshes the invitation ORM object after final commit before response serialization.
- Existing-user auto-accepted invites now send non-actionable `invitation.accepted` notifications instead of `invitation.pending`, so already-accepted users do not see stale Accept/Decline buttons.
- Added invited-user `decline-in-app` backend endpoint and service method. Decline requires the authenticated user's email to match the pending invitation, marks status `declined`, logs `member.invitation_declined`, notifies the inviter, updates the invitee notification, and creates no memberships or role assignments.
- In-app accept now updates the invitee pending notification to `invitation.accepted` and marks it read.
- Notification Center now calls `settingsApi.declineInvitationInApp()` instead of the admin revoke endpoint and invalidates notification/member/invitation/platform-context caches after accept/decline.
- Updated invitation certification tests and report for stale role-assignment reactivation, create success serialization, accept notification state, and decline behavior.

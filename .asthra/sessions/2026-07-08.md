## Frontend Build Investigation — 2026-07-08

- Investigated production build hang after the RBAC permission registry sync hardening pass.
- Found a concrete local artifact issue: `frontend/.next` and child build outputs were owned by `nobody:nogroup`, causing `EACCES` failures when Next tried to write `.next/trace` or unlink manifest files.
- Added `frontend/scripts/prepare-next-build-dir.mjs` and wired it into `prebuild` so non-writable `.next` is moved aside and a writable generated directory is recreated before OpenAPI generation and Next build.
- Added `.next.*` to `frontend/.gitignore` so quarantined generated build artifacts do not appear in git status.
- Verified the recent RBAC frontend changes are backend-driven: permission lists, role checkbox state, registry sync preview, and role saves all use backend permission APIs/types rather than frontend-invented permission codes.
- `npx tsc --noEmit` passed.
- `npm run build` still does not complete: after the `.next` ownership fix it reaches `Creating an optimized production build ...` and stalls. The same stall reproduces in a clean `/tmp` frontend copy excluding `.next*`, so it is not caused by the RBAC sync JSX/type diff or stale `.next` directories.

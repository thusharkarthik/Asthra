  - Source: `useContextVersion()` was enabled immediately, had route-change manual `refetch()`, `refetchOnWindowFocus: true`, and interval polling.

## Task: Reduce Platform Context Scope-Settlement Cascade

**Status**: Implemented. Frontend build passed. Manual network QA still required with running services.

### Root cause

The duplicate-call fix batched frontend scope hydration, but the first unscoped `/context/platform` response still returned no projects/current project. The frontend could select organization and workspace from that payload, then had to fetch `/context/platform?org_id=...&workspace_id=...` to discover projects, then selected the project and fetched the final project-scoped context.

### Changes

- `services/core-service/app/api/v1/context.py`
  - When no explicit scope is provided, Core now resolves deterministic default scope data: first accessible organization, first workspace in that organization, and first project in that workspace.
  - The platform context response now includes projects for the default workspace and default `current_*` records, so the frontend can commit org/workspace/project together.

- `frontend/src/context/platformContext.tsx`
  - Context-version validation is now enabled only after the workspace scope is loaded and project scope is settled.
  - This prevents `/context/version` from validating transient workspace-only scope during initial login.

### Expected request count

- `POST /auth/login`: 1
- `/context/platform`: acceptable max 2 (`unscoped` then final `org+workspace+project`)
- No intermediate `/context/platform?org_id=...&workspace_id=...` when a default project exists
- `/context/version`: 0 or 1, no workspace-only version check during initial settlement

### Verification

- `python3 -m py_compile services/core-service/app/api/v1/context.py` — passed.
- `npm run build` in `frontend` — passed.

## Task: Fix Logout State Cleanup

**Status**: Implemented. Frontend build passed.

### Root cause

Logout from the shell set the logout transition, waited before clearing auth, and only then called `logout()` and navigated. Authenticated React Query cache and workspace/platform context cleanup happened in a later `AuthProvider` effect. During that window, stale platform context could still make the shell evaluate Home/onboarding paths before the unauthenticated redirect settled.

### Changes

- Added `frontend/src/hooks/use-logout.ts`
  - Cancels/clears React Query authenticated cache.
  - Clears workspace scope and context-version snapshot.
  - Exits permission simulation.
  - Clears auth state and redirects to `/login`.

- Updated `frontend/src/layouts/asthra-shell.tsx`
  - Shell logout now clears auth/session state immediately before waiting for transition cleanup.
  - Logout still uses the existing transition/progress behavior.

- Updated `frontend/src/app/settings/account/page.tsx`
  - Account deactivation logout path now uses the same shared cleanup.

- Updated `frontend/src/context/platformContext.tsx`
  - When no token exists, platform context exposes empty auth-dependent data even if React Query has stale cached data.
  - Context-version checks remain disabled without a token.

- Updated `frontend/src/providers/auth-provider.tsx`
  - Hydrated no-token state clears workspace context and React Query cache as a fallback for any auth-loss path.

### Expected behavior

- Logout immediately routes to `/login`.
- Logged-out users do not see Home, shell, or organization onboarding.
- Refresh after logout stays on Login.
- No context/platform or context/version request loop should continue after logout.

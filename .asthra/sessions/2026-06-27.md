## Bug Fix — Role Permission Checkbox Revert + Removal 404

**Branch**: `fix/role-permission-editing`

### Root cause

`addPermissionMutation.onSuccess` and `removePermissionMutation.onSuccess` both invalidated `["settings", "role-permissions", roleId]` BEFORE calling `invalidateSettingsAndContext`. The problem:

1. Role-permissions refetched → UI shows new permission as assigned ✓
2. `invalidateSettingsAndContext` → `["settings", "roles"]` refetched → `RoleService.list()` → `ensure_role_catalog()` → `_sync_role_template_permissions()` — may remove manually-added permission from DB for system roles whose template patterns don't include that permission
3. `rolePermissionsQuery` was already "fresh" (from step 1) → doesn't refetch → UI shows stale "Assigned" state
4. On next unchecked action: DELETE called → backend 404 ("Role permission link not found")

### Fix (`frontend/src/components/settings/settings-admin-views.tsx`)

**Invalidation order swapped** in both `onSuccess` callbacks:
```
before: role-permissions → invalidateSettingsAndContext
after:  invalidateSettingsAndContext → role-permissions
```

This ensures `ensure_role_catalog()` runs (and any backend permission sync completes) BEFORE `rolePermissionsQuery` refetches, so the UI always reflects the authoritative post-sync DB state.

**Optimistic updates added** to both mutations:
- `onMutate`: cancel in-flight queries, snapshot previous data, update cache immediately (instant visual feedback)
- `onError`: rollback cache to snapshot + show error toast
- `onSuccess`: general context first, then role-permissions confirm

## Fix 4 — Role-Permission Sync Made Additive Only (2026-06-28)

**Branch**: `fix/role-permission-editing`

### Problem
`_sync_role_template_permissions()` performed full reconciliation: computed wanted permissions from template patterns, then DELETE'd any DB entry not in the wanted set. This wiped every manual permission assignment made by admins. Template was being enforced as a permanent constraint rather than a starting seed.

Additionally, `ensure_role_catalog()` with `sync_permissions=True` (which runs the expensive permission catalog scan) was triggered on every `list()`, `list_templates()`, and `/me/permissions` API call — essentially on every page load in the settings UI.

### Files changed

**`services/core-service/app/services/role_service.py`**:
- Removed delete block from `_sync_role_template_permissions()`:
  - Gone: `for permission_id in existing_permission_ids - wanted_permission_ids: self.db.delete(mapping)`
  - Sync is now additive-only
- Updated early-exit: `existing_permission_ids == wanted_permission_ids` → `wanted_permission_ids.issubset(existing_permission_ids)`
- `list()`: `ensure_role_catalog()` → `ensure_role_catalog(sync_permissions=False)`
- `list_templates()`: same change

**`services/core-service/app/services/access_control_service.py`**:
- `ensure_role_catalog()` → `ensure_role_catalog(sync_permissions=False)` (called on every `/me/permissions` request)

**`services/core-service/app/api/v1/access_control.py`**:
- Added `from app.services.role_service import RoleService` import
- `sync_permission_registry()` endpoint: after `sync_registry_permissions()`, now also calls `RoleService(db).ensure_role_catalog(sync_permissions=False)` so the admin "Sync Permissions" button seeds role permissions too

### RBAC lifecycle after this fix
1. New service → permissions auto-generated
2. Permission Gap scanner detects missing permissions
3. "Generate Missing Permissions" adds to catalog
4. Permission Registry Sync → syncs catalog AND seeds role permissions (additive only)
5. Superuser reviews → manually assigns permissions to roles
6. Those assignments are permanent truth; sync never removes them

## Fix 6 — Hide Platform Roles from Org/Workspace Invite Modal

**Branch**: `feature/self-serve-onboarding`

### Problem
The invite member dialog in `MembersView` used `groupedAllRoles` which included all role scopes — including platform roles (Platform Owner, Platform Admin, Platform Support). Org admins and workspace admins could see platform roles in the invite dropdown, which they cannot actually grant.

The "Change role" dialog (on member detail view) already correctly used `groupedInviteRoles` (which excludes platform roles in org context) — only the invite dialog was broken.

### Fix (`frontend/src/components/settings/settings-admin-views.tsx`)

Added IIFE-computed `groupedInviteModalRoles`:
```tsx
const groupedInviteModalRoles = (() => {
  const activeRoles = visibleRoles.filter((role) => role.is_active !== false);
  const filtered = isGlobalDirectory
    ? activeRoles.filter((role) => role.scope === "platform")
    : activeRoles.filter((role) => role.scope !== "platform");
  return filtered.reduce<Record<string, RoleRecord[]>>((groups, role) => {
    groups[role.scope] = [...(groups[role.scope] ?? []), role];
    return groups;
  }, {});
})();
```

Invite dialog: changed `<RoleSelectOptions groupedRoles={groupedAllRoles} ...>` → `<RoleSelectOptions groupedRoles={groupedInviteModalRoles} ...>`

### Scope filtering rules
| Context | Roles shown in invite dialog |
|---|---|
| Global directory (`isGlobalDirectory = true`) | Only `scope === "platform"` roles |
| Org context (`organizationId` set) | All `scope !== "platform"` roles |
| Workspace context (`workspaceId` set) | All `scope !== "platform"` roles |

## Fix 9 — Stop-Motion Contextual Help Explainer

**Branch**: `feature/self-serve-onboarding`

### Problem
Previous contextual help animation was a simple chip reveal (all chips fade in left-to-right with 150ms interval). No arrows, no step-by-step progression, no "active step" concept, no CTA sequencing. Felt like a list, not a workflow journey.

### Solution

Upgraded `ContextualHelpModal` to a stop-motion explainer: steps build progressively with animated arrows between them, active step highlighted, past steps dimmed but visible, CTA appears after final step.

### Files changed

**`frontend/src/lib/help-registry.ts`**:
- Added `HelpStep = { label: string; icon?: string }` type (exported)
- Changed `HelpContent.steps` from `string[]` to `HelpStep[]`
- All 17 registry entries enriched with emoji icons
- Step labels shortened for compact card display on routes specified in task (e.g. "Create Work Item" → "Work Item", "Capture Idea" → "Idea")
- `/settings/roles` step "Assign Permissions" shortened to "Assign Perms" to fit on one line
- `/settings/permissions` step "User Assigned Role" shortened to "Assign Role", "Permission Active" to "Perm Active"

**`frontend/src/components/platform/contextual-help.tsx`**:

New sub-components:
- `AnimatedArrow({ visible })`: `overflow-hidden` container transitions `width: 0 → 32px` and `opacity: 0 → 1` over 200ms. Contains thin line (`div.h-px.flex-1`) + `→` text.
- `StepCard({ step, index, visible, active })`: Active card = `bg-primary text-primary-foreground scale(1.05) opacity-1`. Past card = `bg-muted opacity-0.65`. Hidden card = `opacity-0 translateX(1rem)`. All transitions via `transition-all duration-300`. Emoji icon at `text-base`; fallback is numbered circle.

New state:
```tsx
const [headerVisible, setHeaderVisible] = useState(false);   // title/desc fade-in
const [visibleSteps, setVisibleSteps] = useState(0);          // how many cards revealed
const [arrowsVisible, setArrowsVisible] = useState<boolean[]>([]); // which arrows shown
const [ctaVisible, setCtaVisible] = useState(false);           // footer row
```

Animation sequence (all timeouts collected in `timers: number[]`, cleared on cleanup):
| Time | Event |
|---|---|
| +16ms | `headerVisible = true` → title fades in (300ms), desc fades in (200ms + 150ms delay) |
| +700ms | Step 0 card slides in (first step, no preceding arrow) |
| +1550ms | Arrow 0→1 animates width (200ms) |
| +1750ms | Step 1 card slides in |
| +2400ms | Arrow 1→2 animates |
| +2600ms | Step 2 card slides in |
| … | (each subsequent step adds 850ms) |
| +last_step + 300ms | `ctaVisible = true` → footer fades in |

Per-step formula: `base = 700 + index * 850`. Arrow at `base`, card at `base + 200` (except step 0: card at `base + 0`).

Special cases:
- `steps.length === 0`: `ctaVisible` set at +300ms immediately (no animation needed)
- Close/reopen: all state resets to 0/false/[] on `!open`, timers cleared by cleanup

Modal width upgraded from `max-w-sm` (384px) → `max-w-xl` (576px) to fit 5 horizontal step cards + 4 arrows (~520px estimated).

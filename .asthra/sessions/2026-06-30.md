# Session Notes — 2026-06-30

## Task: Core Migration 0013 Duplicate role_assignments Unblocker

### Issue

Core failed during Alembic startup at `0012_access_control_foundation -> 0013_scoped_membership_foundation` with:

`sqlite3.OperationalError: table role_assignments already exists`

Because Core failed startup, gateway login requests returned `502 Bad Gateway`.

### Root Cause

`0013_scoped_membership_foundation.py` unconditionally created `role_assignments`, `project_memberships`, their indexes, and `team_members.status/joined_at`. In local SQLite dev databases, Core bootstrap/model metadata can create missing model tables before Alembic reaches 0013, leaving the database with `role_assignments` already present while the Alembic version remains before 0013.

### Fix

- Added Alembic inspector helpers to `0013_scoped_membership_foundation.py`.
- Guarded `op.create_table` for `role_assignments` and `project_memberships`.
- Guarded index creation for both tables.
- Guarded `team_members` column/index additions.
- Kept RBAC architecture unchanged: `role_assignments` remains the source of truth; no `user_roles` usage added.

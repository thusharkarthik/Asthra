# Asthra Branching Strategy

Feature branches should describe the specific platform area being changed.

## Naming

Examples:

- `feature/core-auth`
- `feature/api-gateway-foundation`
- `feature/shared-platform-standards`
- `fix/core-health-readiness`
- `docs/platform-governance`

## Rules

- Keep branch scope narrow.
- Do not mix unrelated service changes.
- Documentation-only branches should not change service logic.
- Shared package branches should not refactor existing services unless explicitly requested.

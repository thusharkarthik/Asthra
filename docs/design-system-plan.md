# Asthra Design System Plan

Asthra needs a practical product design system for dense operational work across many modules.

## Principles

- clear hierarchy over decorative layout
- predictable navigation
- compact but readable data surfaces
- accessible colors and focus states
- consistent forms, tables, filters, and detail panels

## Component Areas

- app shell
- sidebar and top navigation
- workspace/project switchers
- tables and data grids
- forms and validation states
- modals and drawers
- comments and activity feeds
- dashboards and widgets
- notification surfaces
- AI assistant panel

## Future Component Library

The frontend should adopt or build on a component library that supports:

- TypeScript
- accessible primitives
- theming
- composable layout
- icon support

## Rules

- Do not create one-off visual systems per module.
- Keep modules visually consistent while allowing domain-specific workflows.
- Design for repeated daily use, not marketing presentation.

# Asthra Frontend Modules

Future frontend modules should mirror Asthra product suites and service boundaries.

| Module | Backing Service | Purpose |
| --- | --- | --- |
| Core | core-service | identity, organizations, workspaces, projects |
| Flow | flow-service | work items, boards, comments, labels |
| Docs | docs-service | spaces, pages, comments, tags, search |
| AI | ai-service | conversations, prompts, completions |
| Memory | memory-service | sources, documents, chunks, retrieval |
| Discover | discover-service | ideas, feedback, roadmap planning |
| Desk | desk-service | tickets, queues, SLAs, incidents |
| Pulse | pulse-service | alerts, incidents, on-call, status pages |
| Dev | dev-service | repositories, deployments, services |
| Collab | collab-service | threads, announcements, updates |
| Automation | automation-service | workflows, triggers, actions |
| Connect | connect-service | integrations, webhooks, sync jobs |
| Guard | guard-service | policies, compliance, risks |
| Insights | insights-service | dashboards, metrics, reports |
| Media | media-service | media assets, transcripts, annotations |

Each module should share navigation, layout, identity context, notifications, and design system components.
